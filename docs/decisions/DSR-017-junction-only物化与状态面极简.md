# DSR-017：junction-only 物化与状态面极简（storage 五表 → 两表）

> 状态：已确认（2026-09-01，design-spec-workshop 新基线重设计，用户逐项裁定），代码实施待执行；与 DSR-014/015/016 合并为一次实施批次（登记于 `../TODO.md`）。

## 上下文

2026-09 需求基线重构（`../需求.md`）改变了状态面与物化机制的成立前提：

- 本地导入、同步矩阵与健康视图、工作区既有条目接管全部废止为非目标；C-03 升级为「对用户自有 skill 绝不重命名、覆盖或删除」；C-04 把自动执行限定为「按期望在空闲目标建立**链接**、摘除可证明归本插件所有的**链接**」——措辞只提链接，copy 兜底（在目标创建真实目录）不在边界内。
- R-12 只要求工作区删除后「仅报告问题」；未匹配报告与「N 个组使用」计数均可从 settings 意图 + `workspaceRegistry` 现算。
- DSR-006 当年保留 `projects` 镜像的唯一理由是「distributor CLI 独立运行时无法解析项目级目标」；新基线非目标「不与既有 CLI 工具互通」使该理由失效（其重访条件 2 实质触发）。
- `backups` 登记表与备份目录 + `_backup_meta.json` 是同一事实的两个来源，并集合并逻辑本身就是漂移源。
- 既有对账存在语义缝隙：步骤 1 摘除「在 `synced` 表但不在期望集」的记录，而孤儿清扫段与 AC-10 要求「改配目录后指向旧目录的链接保留为孤儿不清理」——有记录与无记录的链接在改配目录后待遇互相矛盾。
- 本机为 Windows + NTFS，junction 跨本地卷可用且已被现状插件实测（旧设计文档记录项目级链接正常工作）；非目标明确「不为其他机器设计安装器」。

## 真实方向与评价

- 方向 A：junction-only + `synced`/`projects`/`backups` 三表删除。归属证明收敛为单判据——realpath（悬挂链接以 `readlink` 原始目标兜底）落在当前配置目录内；摘除与孤儿清扫合一；不变式升级为「本插件在 DSH 根与工作区根只创建 junction，永不创建或删除真实目录」。AC-10 缝隙自动消除（旧库前缀外的链接不满足判据，永不触碰）。代价：junction 不可用的环境（非 NTFS 卷、奇异权限）失去 copy 静默降级，只能行状态「挂载失败」+ 修复提示词引导；旧版本遗留的 copy 物化目录升级后按「目标被占用」处理，需一次性按修复提示词清理。
- 方向 B：保留 copy 兜底与 `synced` 表（上一轮裁定的 3 表形态）。环境适应性最好；代价是保留整套 copy 语义与哈希簿记，与 C-04 的链接措辞存在张力，AC-10 缝隙还需额外补丁规则弥合。

评价：在本机既定环境（Windows NTFS、单用户、不分发他机）下，方向 B 保护的场景概率低，而其概念与簿记成本常驻；方向 A 把 C-03/C-04 红线变成机器可验证的单一不变式，且「junction 失败需人工介入」恰是 R-17 修复提示词机制的设计场景。

## 最终决定

采用方向 A（2026-09-01 用户确认）：

1. 物化只建 junction；junction 失败即该目标记「挂载失败」，转行状态 + 修复提示词，不降级 copy。`sync` 方法的物化方法参数随之删除。
2. 归属证明单判据：realpath（悬挂链接 `readlink` 兜底）落在当前配置目录内。该判据由 `mount/inspect.js` 的 `findOrphanLinks` 单源承载，对账摘除、`remove` 摘除与行状态走查三处共用。
3. storage 域收敛为两表：`skills`（入库元数据）、`check_cache`（检查结果缓存）；`synced`/`projects`/`backups` 表删除。备份事实源 = 备份目录 + `_backup_meta.json`；工作区信息现算，不再镜像。
4. 域 `version` 保持 1：被删三表均为可再推导的运行时投影，无需迁移代码，新 spec 首次写入自动抹除未声明旧表；旧七表意图迁移（`intentMigrated`）不受影响。
5. `skills.origin` 只新登记 `"github"`；存量 `"local"`/`"self"` 记录兼容读取并视为 self（无上游操作、无删除入口）；`origin_path` 字段仅供旧记录通过校验，不再写入。
6. `remove` 仅限 `origin: "github"` 条目：删除前一律自动备份（取消 `keepFiles` 选项；目录已缺失时无物可备，`backup` 为 `null`）；自有 skill 无删除入口，由用户在文件系统自管，库视图下次扫描即消失。
7. 写库目录一律原子换装（同卷临时目录构建 + rename 交换）：junction 使库内容对 DSH 实时可见，半写目录会被直接挂出，必须消除该窗口。

## 直接后果

- **取代/回退**：DSR-004（项目级既有 skill 最小接管）被新基线非目标推翻，本决定显式回退；DSR-006 的 `projects` 镜像后果（CLI 兼容镜像）被本决定取代，其「工作区唯一来源、不提供项目写操作」核心保留；DSR-015 的模块清单由本决定修订（`model/workspaces.js` 删除、`mount/inspect.js` 收缩、`inbound/acquire.js` 去导入、摘除与孤儿清扫合一）；DSR-008 涉及同步矩阵的后果（05 帧徽章配色）失效，其余（⋯ 菜单、复选批量入库、状态直显）保留。
- **波及文档**：`../technical-details/目录配置与状态存储.md`（两表形状、备份事实源、不变式）、`../technical-details/入站操作.md`（操作集收缩、remove/备份/恢复语义、原子换装）、`../technical-details/挂载与同步.md`（junction-only、单判据、对账三步、行状态走查）、`../technical-details/插件运行时.md`（方法表 11、视图两页）、`../项目结构设计.md`（模块清单）全部就地重写；`../README.md` 状态区与 `../TODO.md` 同步。

## 重访条件

- 出现多机器分发或非 NTFS 环境支持需求时，重访 copy 兜底（届时 `synced` 表与哈希簿记随之一并恢复评估）。
- DSH 的 skill 发现语义变化（如不跟随 junction）时，重访物化机制。
- 需要物化历史审计（谁在何时建过哪些链接）时，重访物化台账。
