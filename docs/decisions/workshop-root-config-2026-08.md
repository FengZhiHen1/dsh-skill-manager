# DSR-005：车间根由设置配置，空即未配置

## 上下文

设计基线（DSR-002）把车间根硬编码为 `E:\Project\Skills`。用户调整要求：支持从设置中的插件配置选项配置本地 skill 目录，默认为空。语义已确认：空即未配置——插件不访问任何车间目录，直到用户在设置中配置。

## 真实方向与评价

- 方向 A：车间根可配置，为空时回退默认 `E:\Project\Skills`。基线语义不变，只增加覆盖能力；但 `E:\Project\Skills` 仍以默认值形式写死在设计中，未配置状态不存在，"默认为空"只是选项层的表达，实际默认仍是固定路径，本机路径依赖未解除。
- 方向 B：车间根可配置，为空即未配置。插件不假设任何车间目录；未配置时进入未配置状态（管理操作返回 `workshop-unconfigured`，技能页显示引导）；配置后该目录成为唯一车间根，立即生效。代价：改变 DSR-002 的 SSOT 路径假设，需要未配置状态语义、配置校验与缺失文件语义。
- 方向 C：固定车间之外，支持在设置中配置多个本地 skill 目录参与分发（类似 DSH 核心 `customSkillDirs` 默认 `[]`）。多源并存；与"单一车间唯一事实源"基线冲突，v1 没有证据需要多车间并行。

## 最终决定

采用方向 B。依据：用户明确确认"空即未配置"（2026-08-16）；该语义使设计与本机路径解耦，未配置状态成为插件的正式状态而非错误；方向 A 与用户确认的语义不符；方向 C 引入多车间复杂度，无证据需求。

## 直接后果

- DSR-002 的"插件写入 `E:\Project\Skills\…`"后果被本决定限定：仅当配置指向该路径时成立；本目录设计文档中的车间根一律按"配置值"表述，不写死路径。
- 插件注册 settings 命名空间 `skill-manager`，字段 `workshopDir`（本地 skill 目录），默认空串；Client 在设置"插件"区注册配置卡片编辑该字段。
- 未配置：所有车间 RPC 统一返回 `workshop-unconfigured`（含 search/repo-skills，避免"可搜不可落"的半可用状态）；技能页显示未配置引导。
- 配置校验：非空时必须是绝对路径且目录存在；不通过则拒绝保存。`applies: live`，保存后立即生效，无需重启；每次 RPC 按当前配置值读取车间根。
- 更换车间根：旧车间的挂载链接不在新根前缀内，保留为孤儿（安全边界自动生效，不删除）；新车间的共享文件按空骨架起步。
- 非 Git 仓库的车间：自动提交降级为跳过并提示；其余功能照常。

## 重访条件

- 出现多车间并行或多源分发需求时，重访方向 C。
- 需要出厂默认车间（默认指向固定路径）时，重访方向 A。
