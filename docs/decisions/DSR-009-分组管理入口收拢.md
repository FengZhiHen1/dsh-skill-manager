# DSR-009：分组管理入口收拢——新建模态、卡片内改名/删除

## 上下文

设计稿落地时发现 01/07 帧的「＋ 新建 / 管理分组」chip 从未定义点按后的界面，而实现侧（client.js）把分组的 新建/改名/删除 全部堆在胶囊行：每个命名组胶囊后跟「改名」「删」文字链接，行尾再放内联输入框 + 新建按钮。视觉上胶囊行拥挤（见 2026-08-19 test profile 实测截图），与设计稿的克制风格不符，且 chip 语义（管理分组）没有对应界面。

## 真实方向与评价

- 方向 A：chip 点开分组管理弹层（列表 + 行内改名/删除 + 底部新建输入）。功能集中，但为低频操作引入一个新弹层形态；且改名/删除的对象是"当前正在配置的分组"，与胶囊行解耦后反而要在列表里再找一次目标组。
- 方向 B：胶囊行只保留「＋ 新建分组」，点按开**模态对话框**（与 06 帧更新确认同一遮罩语言）；改名/删除入口移到「当前分组」卡片标题行——操作对象正是正在查看/配置的组，上下文最近。

## 最终决定

采用方向 B（2026-08-19 用户确认，设计稿 09 帧定义）：

1. 胶囊行收敛为纯选择器 + 「＋ 新建分组」chip；移除每组后的改名/删链接与行尾内联新建输入。
2. 新建分组走模态对话框：组名输入 + 「新组复制『默认』组的挂载规则作为起步」提示（既有实现行为固化为设计语义）+ 取消/新建。
3. 改名入口在「当前分组」卡片标题行，点按后标题行变为内联编辑态（输入框 + 保存/取消）；改名立即生效，成员与挂载规则同步改名。
4. 删除入口同在卡片标题行（红色），执行前确认；删除后成员回落「默认」组。
5. 边界：「默认」是虚拟组，卡片不出现改名/删除入口；「全部」视图无当前分组卡片。

## 直接后果

- 设计稿：09 帧（新建模态 + 卡片管理入口 + 改名中状态）；01/07/08 chip 文案收窄为「＋ 新建分组」。
- 实现：`client.js` 分组行重构（移除 GroupCreate 内联输入与每组改名/删按钮），新增新建分组模态组件；GroupScopePanel 标题行增加改名（内联编辑）/删除（确认后 groups/op delete）操作；Host `groups/op` 既有 create/rename/delete 语义不变，无需改动。

## 重访条件

- 组数量多到需要批量管理或搜索时，重访集中的管理弹层（方向 A）。
- 改名需要撤销/历史时，重访"立即生效"语义。
