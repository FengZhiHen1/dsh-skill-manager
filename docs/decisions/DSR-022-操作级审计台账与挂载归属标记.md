# DSR-022：操作级审计台账与挂载归属标记

## 上下文

2026-09-09 事故：用户报「`E:\Project\Skills` 中 `yao-meta-skill` 的挂载链接不见了」，本会话穷举取证**无法归因**。事后盘点出四条独立原因，全部指向设计缺口而非检索不力：

1. **插件自述无台账**——`src/core/mount/reconcile.js:29` 注释原文：「摘除 = 孤儿清扫（同一归属判据，**无第二张台账**）」。
2. **对账结果不落盘**——`reconcile()` 的 `results`（含 `name`/`target`/`action`/`reason`）返回调用方 → UI toast 一闪即弃。`core/**` 里全部持久化写入点只有 `store.putSkill` / `store.putCheck` / `deleteCheck`（skills 表 + check_cache），**没有任何一张表记链接操作**。
3. **日志只有错误路径**——全插件仅 4 条日志调用（`adapter/index.js:22,38,50,90`，皆 `logger.warn`）；**对账成功时零输出**。`logger` 虽注入 `buildApi`（`adapter/index.js:75`），挂载路径一次都没用它。
4. **环境侧退路全断**——目标仓库 `.gitignore:9` 忽略整个 `.dsh/`（`git check-ignore -v` 实证）→ VCS 无痕；junction 删除不进回收站；NTFS 只留父目录一次 `LastWriteTime`（`E:\Project\Skills\.dsh\skills` = 09-09 **09:01:32.547**，比 `homes\test\settings.yaml` 写入 09:01:32.**315** 晚 **232ms**，与插件 200ms 防抖同量级——**这是时间签名，属推断，不是证据**），且不带文件名；Windows junction 的 reparse 数据放不下自定义来源标记。

根因陈述：归属判据是 **realpath 前缀**（`core/mount/inspect.js:36-41`、`materialize.js:65,106`），链接一旦被删，**「曾被 A 实例建过」与「从未存在」在系统里不可区分**。

同一次排查还坐实第二件事：工作区注册表按 HOME 存放（`storages/workspace.json`），试验 HOME 从生产继承来 **13 条真实项目**（含 `E:\Project\Skills`、`E:\Project\DSH_Plugins`）——配置里残留一条 `scope: project` 挂载，对账就会直接往真实项目建/摘链接；两个 HOME 的实例共用同一配置目录时**互摘链**（已记入 `technical-details/挂载与同步.md`）。本 DSR 的归属标记就是封这条通道的。

## 真实方向与评价

**归属判据三案**：
- 甲（现状）realpath 前缀：零文件成本；但跨实例互摘、事后不可归因——今天的事故通道。
- 乙 链接名编码 owner（前缀/后缀）：**不可行**——DSH 按目录名识别 skill（`knowledge/v0.1.2-rc.1/agent/23-skill.md`），改名即改语义。
- 丙 本 HOME 的**托管清单**（manifest）：摘除权改为「我的清单里登记过」，归属精确、可归因；代价是需要一次性认领（adopt）迁移既有链接，以及清单本身成为新的受管状态。

**丙 的落点三选**（2026-09-09 复评，用户确认丙-c）：
- 丙-a 每挂载根一份就地清单（`.dsh/skills/.managed.json`）：随项目同生同灭、无悬挂登记。❌ 否决三条理由——① 撞 `目录配置与状态存储.md` 的既有原则「目录内不出现插件状态文件」（该原则虽是为配置目录立的，但「状态归 HOME」的方向明确）；② 判 orphan 需要跨「全局根 + N 项目根 + pi 根」聚合，按目录切碎后每趟判定读 1+N+1 份文件并处理部分不可读，而摘除是全局决策；③ 依赖「DSH skill 根扫描容忍非目录条目」这一未复核前提（丙-c 下该前提整体消失）。
- 丙-b 每 HOME 一份中心文件（`$DSH_HOME/skill-manager/managed-links.json`）：不进任何扫描根、判定单次读取。❌ 否决理由：**它只是把已有落点复制一遍**——同 HOME 已有 `storages/skill_manager.json` 承载运行时状态，平台还自带「持久化先行」单写链与 `update()` 链上原子 RMW；新增文件等于自己再造一套同等语义（`fsys.writeJson` 现为零调用方孤儿，走丙-b 才"转正"，那不是采用它的理由）。
- **丙-c（选定）storage 域新表 `managed_links`**：净新增文件 **0**；写链、原子 RMW、`domain/changed`、`version` 校验全部现成；出库时「删库目录 + 删登记」落进同一次文档写入，天然不出现「目录已删、登记仍在」；隔离强度与实例隔离强度一致（按 HOME）；符合「投影归 storage 域」的既有归属划分。代价：`writeJson` 转为应删除的真孤儿；清单不再是纯追加形态（仍在 `skill_manager.json` 内可 grep，一行一条记录）。

**为什么清单与台账不能合并成一个文件**（复评确立的判据，第 1–9 条与第 10 条的分界）：台账承载**历史**，必须截断（第 9 条双上限）；清单承载**当前状态**，绝不可截断——同文件混放则轮转会把仍存活的登记一起截掉，而「宁可残留」的默认姿态意味着丢登记 = 永久不可回收。备份是这条判据的反面正例：`backups/_backup_meta.json` 就地自描述成立，正因为「一个目录 = 一条记录且同生同灭、永不轮转」。

**审计埋点两案**：
- 在每个业务调用点手写审计调用：分散，新增变更点必漏（今天就是因为变更点分散在 5 个模块）。
- **收敛到 fs 咽喉层**：变更只发生在少数几个原语调用上（实测清单见下），一处埋点覆盖全部变更面，且天然记到失败分支。选此。

**读取面两案**：
- 提供 `audit` RPC 方法 / 页面「操作记录」面板：查询方便，但增加契约面、UI 成本与版本兼容负担。
- **只留 JSONL 文件，Agent 按需自查**（用户 2026-09-09 决定）：零契约成本。其代价必须被正视——**文件格式即接口**，因此格式约束写进本 DSR（见「最终决定」第 7 条），违反即视为破坏接口。

## 最终决定（2026-09-09）

1. **台账位置**：`$DSH_HOME/skill-manager/audit.jsonl`，与 `library`/`backups` 同由 `ctx.dshHomePath('skill-manager', …)` 派生（`adapter/index.js:60` 同款）。它**不参与对账**、不被「出库」删除、不进任何期望集。
2. **粒度 = 单操作**：一次链接新建 / 摘除 / 重建、一次目录换装或覆盖下载、一次 exclude 托管块写入 = 各一条记录。**批次摘要不能替代单条**（这是本 DSR 的立项理由）。
3. **两段式**：副作用之前落 `pending`，之后补终态（同 `opId`）。进程中途被杀 → 留下**无终态的 `pending`**，它本身就是「动手了但没记完」的证据。
4. **覆盖面 = fs 咽喉点清单**（实测枚举，逐点埋；新增变更点必须同步登记进本清单。⚠ 行号标的是**变更发生在哪里**，不是「每行一条记录」——记录粒度按语义 op 聚合，实现期确立的五条聚合规则见文末「实现状态」R1）：
   - `core/mount/materialize.js:23,26`（`removeLink`：删链接 / 递归删）
   - `core/mount/materialize.js:54`（`mkdir` 父目录）、`:89`（`symlink` 建 junction）
   - `core/mount/reconcile.js:93`（`.git/info/exclude` 托管块写入）
   - `core/inbound/zipball.js:115,116,150,153`（下载落盘、stage 目录、`cp`）
   - `core/inbound/backups.js:45,54,71,178`（备份目录建立/回滚、源目录删除）
   - `core/base/fsys.js:86-96`（原子写/删受管文件）、`:208-242`（`atomicSwapDir` 换装与回滚）
5. **每条记录的字段**（单行完整 JSON，键名冻结）：`seq`（进程内单调递增，防时钟回拨与并发乱序）、`ts`（ISO-8601 带时区）、`opId`（pending 与终态配对）、`phase`（`pending`/`done`/`failed`）、`actor`（`{entry: rpc|watch|tool|boot|client, method}`）、`home`、`profile`、`pid`、`procStarted`、`skill`、`path`（被改对象绝对路径）、`target`（链接目标 realpath）、`srcRoot`、`reason`（判据/触发原因，如「孤儿链接（归属本插件且不在期望集）」）、`configGen`（本次读到的配置代次，与 `shared.bundleGen` 同源）、`code`/`error`、`durationMs`。
6. **不记只读**：`overview`/`check`/`diff` 等不改 fs 的方法零记录。
7. **格式即接口**：一行一条完整 JSON；绝对路径原样（不缩写、不正反斜杠混用——统一 `path.resolve` 产物）；**不压缩、不加密、不分片到需要工具才能读的形态**；轮转后仍是 `*.jsonl`，保证 `Select-String`/`rg` 单命令可答「这条链接被谁在什么时候动过」。
8. **noop 不逐条**：每次操作批次结束落一条 `phase:'summary'`，带 `evaluated`（期望条目数）/`orphans`（孤儿数）/`changed`（终态非 noop 数）。用途是区分「执行了但没变化」与「根本没执行」。
9. **双上限截断**：> **5000 行** 或 > **90 天**，先到先生效；实现为「写临时文件 + `rename` 原子替换」，检查时机 = 批次结束后（不是每条写入都重排）。截断本身也要落一条 `phase:'rotate'` 记录（记删掉了多少行、时间范围），否则台账会出现无法解释的空洞。
10. **归属标记（manifest）= storage 域新表 `managed_links`**（丙-c，用户 2026-09-09 确认）：
    - 键 = 链接绝对路径，归一口径与 `findOrphanLinks` 现有判据同构（`path.resolve` 产物再 `toLowerCase()`，Windows 大小写不敏感）；值 = `{ target（目标 realpath）, entry, skill, created_at, opId }`。表形状与其**唯一事实源/可清空性**契约归 `../technical-details/目录配置与状态存储.md`「`managed_links` 表」节拥有，本条只记取舍。
    - **摘除权只来自登记**：`findOrphanLinks` 与 `remove` 摘链一律改为「命中 `managed_links` 键」才允许删；realpath 前缀判据**不删除但降级**——它此后只用于「不夺取外来物」的下界（外来真实目录、指向库外的链接仍一律不碰），不再作为「可以删」的依据。
    - **自检重建同受此约束**（复评补齐的缺口）：`materializeOne` 里「目标已是链接且指向库内他处 → 摘除重建」这条路径同样要求登记命中；否则等于从另一条通道把摘除权还给前缀判据。未登记且指向库内他处的链接 → 只报告「非本实例所建，不夺取」，不改。
    - 建链成功、出库摘链、孤儿摘除三处是**常规**写入点（表形状一节按「三处 + adopt」计数），第 11 条的 adopt 为第四处且一次性；表**不参与期望集推导**（期望集仍纯由 settings 意图 × 工作区投影现算），也不进库视图不变式。
    - **缺失姿态 = 宁可残留**（用户 2026-09-09 确认；取舍理由：误摘不可逆，漏登可由台账与 adopt 收口）：登记读不到的一律**不摘**，并把「有 N 条链接未登记、本插件不会管理它们」显式报进 warnings，交用户判断（第 13 条给出三条不可混淆的分支）。
11. **一次性认领（adopt）**：`managed_links` 表首次出现（升级后第一趟对账，表现为「表空而现场有链接」）时，把「realpath 前缀判为自有、但无登记」的既有链接**认领写入表并落一条 `op:'adopt'` 台账记录**，不直接摘除——否则升级瞬间会把本实例早年建的链接一律判为外人所有而永久放任。adopt 是**一次性的兼容通道**：认领完成即关闭，此后前缀判据不再授予任何摘除权（判据见第 10 条）。反向分歧（表有登记、现场无链接）＝**悬挂登记**：保留登记并报告，等期望集重建时自愈；不因为现场没有就删登记（删了就等于把「谁建过」这条不可重算的事实丢掉）。
12. **实现顺序**：A 台账（1–9）→ B 归属标记（10–11）。A 先行仍然成立：纯追加写、不碰任何判据、零回归风险，且 B 的 adopt 争议需要 A 的记录来核对。**原列的 B 硬前置（DSH skill 根能否容忍非目录条目）随丙-c 定型整体消解**——清单不再落在任何被扫描路径内，无需核对也无需实测场验证。B 的开工次序：表声明与门面（`core/model/store.js` + `adapter/storage.js`）→ 三处常规写入点（建链 / 孤儿摘除 / 出库摘链）→ 判据切换（含自检重建与第 13 条三分支）+ adopt → 回归闸第 6、7、9 条。
13. **登记表读不到时的三条分支**（「宁可残留」的精确化，实现不得合并处理）：
    - **域打不开**（`version-mismatch`/`invalid-record`/IO 失败）：既不能摘也不能认领——此时无法区分「我的表被清空」与「我看不见别人的表」，允许 adopt 就等于把别的实例的链接认领回来、事故原样重演。动作 = **零变更 + 警告**（与本文档既有「域打开失败不拖垮 Host」一致，但此处要求同时关闭 adopt 通道）。
    - **域正常而表空、现场存在前缀自有链接**：第 11 条的 adopt 触发条件成立 → 认领登记，不摘。
    - **表非空、部分现场链接不在表内**：这些一律视为外人所建，**永不摘**（含用户手工建的、含 HOME 搬迁后路径变旧的），只报告条数。

## 直接后果

- 每次对账多 N 次追加写（N = 实际变更数，稳态收敛时 N=0 只多一条 summary）；台账自身写失败**必须进 `results` 与健康面**，不得静默——否则又是一次「没记下来」。
- 归属判据从「推断」变成「登记」：跨实例互摘链被物理封死（A 实例的 `managed_links` 里没有 B 实例建的链接 → 摘不到）。代价是这张表成为新的受管状态，需与链接现场自愈对账（现场有链接、表无登记 → adopt；表有登记、现场无链接 → 保留登记并报告，见第 11 条）。
- 隔离强度**只按 HOME**：两实例共用 HOME（AGENTS.md 红线已禁）时 `storages/skill_manager.json` 本就同档，表也共用，B 案不额外提供保护——它封的是「分 HOME 但共用配置目录」那条通道。
- 事故可追责：下次同类问题，一条 `rg 'yao-meta-skill' audit.jsonl` 就能给出时间、入口、pid、HOME 与原因。
- 对账**从此失去「清扫一切」的能力**（「宁可残留」的直接代价，有意取舍）：任何未被本 HOME 登记的链接——别家实例建的、用户手工建的、HOME 搬迁后路径变旧的——一律长驻残留，只报告不处理。残留是可查可清的（台账 + warnings 定位，用户手工删或重新纳入期望集），而误摘不可逆。
- 与 DSR-017（junction-only 物化与状态面极简）有张力：本 DSR 新增**一份文件**（`audit.jsonl`）与**一张表**（`managed_links`），是对「状态面极简」的有意让步——理由是 DSR-017 省的是**可推导**的缓存，而归属与追责记录**不可推导**，丢了就永久丢了。落点选丙-c 正是为把让步压到最小：**介质文件总数不变**（新表进已有域文档）。

## 验证计划（成功判据，实现时逐条落为回归闸）

1. 单测（tmp 根）：建链 → 台账出现 `pending` + `done` 两行、同 `opId`、字段齐全；断链 → 出现 `reason` 含「孤儿」的摘除记录。
2. 崩溃路径：在 `symlink` 前注入抛错 → 台账留下**无终态 `pending`**，且 `results` 里有对应 error。
3. 只读不变量：连续调 `overview`/`check` 二十次 → 台账行数零增长。
4. noop 语义：稳态收敛下触发一次 `sync` → 只多一条 `summary`，`changed: 0`。
5. 双上限：灌 5001 行 → 触发截断并落 `rotate` 记录；行数回到 ≤5000 且保留的是最近的。
6. 跨实例隔离（B）：两个 tmp HOME（两份独立 store 门面 + 两份独立挂载根现场）**共用同一配置目录**，A 实例对账后 B 实例的链接必须原样存在——这是 09-08 事故的对照组，把摘除判据退回前缀法即红。`buildApi` 收 `getStore` 注入点，故本条可在 unit 层复现，不需起进程。
7. adopt（B）：预置「前缀判为自有、表无登记」的链接 → 首趟对账不摘除、写入表、落一条 `op:'adopt'`；第二趟对账不再重复 adopt。反向：预置「表有登记、现场无链接」→ 登记保留、报告出现悬挂、不产生删除动作。
8. 现场冒烟（按红线由用户在 test 实例执行）：改一次分组挂载，把 `audit.jsonl` 新行贴回来核对字段可读性。
9. 宁可残留三分支（B，第 13 条）：① 令 `getStore` 抛错（域不可用）→ 一趟对账**既不摘也不认领**且 warnings 有明确一条；② 表空 + 现场有前缀自有链接 → 全量 adopt、零摘除；③ 表内只登记一半 → 未登记的那半**原样存在**，报告条数。
