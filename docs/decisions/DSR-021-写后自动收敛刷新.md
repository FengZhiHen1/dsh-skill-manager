# DSR-021：写后自动收敛刷新——客户端驱动 sync，后台对账共队

## 上下文

用户意图（settings）与文件系统现场（junction）之间由对账器异步收敛，中间必然有延迟窗口。2026-09-09 走查报出两项同根症状：

1. 调整 skill 配置（换组、禁用、改挂载）后界面不反映新现场，必须人工点「↻ 刷新」——AC-04「换组或改挂载后立即按新期望生效」在**视图面**没有兑现路径。
2. 新建分组提示「已创建」，但组列表里找不到它；同一个组却又出现在行 ⋯ 菜单的「移动到分组」里。

代码事实（`src/adapter/index.js`、`src/client/section.jsx`、`src/client/manage.jsx`）：

- 客户端在 `settings/document-updated` 到达时**立刻**重读 `overview`；Host 对账器此刻还在 200ms 防抖窗口里，读回的必然是旧物化现场，且收敛之后再无人重读。
- 后台对账 `api.sync({})` 直接调用，**不进** `createDispatch` 的 WRITE FIFO——读屏障（`writeQueue.busy` 时读等写结算）看不见它，防抖窗口后重读也可能撞上对账做一半。
- 两路全量对账并发时对同一目标同时建链，后到者 `symlink` 吃 `EEXIST` → 误报「挂载失败」。
- 分组导航列高封顶内滚（`maxHeight: 320`）：13 行（全部 + 默认 + 11 命名组）约 377px，末两行落在折线以下；`doCreateGroup` 只看客户端撞名预检就弹成功 toast，不看写是否落定。

DSR-013 的重访条件「快照延迟在实测中产生可感知的一致性投诉」由此**触发**：本记录收口视图面，不改 DSR-013 的读路径决定（读仍不入队）。

## 真实方向与评价

- 方向 A：Host 侧收敛完成后主动推事件给客户端。语义最干净（谁变完谁说话），但 Host→Client 事件是**白名单转发**的（`packages/api/remotes/src/remote-events.ts`，rc.1 共 18 项，第三方插件不得新增自定义推送）——此路要改 DSH 本体，插件侧不可得。
- 方向 B：客户端延时重读（把 `load()` 推到 200ms 之后）+ 依赖读屏障。零新协议，但把正确性押在两个魔数的大小关系与 Host 事件循环不被压上；对账若在 300ms 才入队，读依然抢跑，且读屏障看不见未入队的后台对账。
- 方向 C：客户端在写落定后**显式 `sync` 一次**再重读 `overview`；同时把后台防抖对账改注入同一条 WRITE FIFO。收敛由调用方驱动，不赌时序——`sync` 返回即现场已按当前意图收敛并预热读缓存，紧随的读必是新鲜快照。代价：一次编辑突发多做一趟幂等对账（收敛态下只是 stat 走查，`↻ 刷新` 本来就在做同一件事）。
- 组列表可见性与成功话术同 A/B/C 正交，两案：① 选中项滚入视野（保留列高封顶）；② 取消封顶让列自增长（放弃「组数无上限」的既定形态）。① 不改变信息架构，② 在 50 组时把右栏挤没。

## 最终决定

采用方向 C + ①（2026-09-09）：

1. 客户端 `editConfig` 返回 `Promise<boolean>`（权威快照与尝试值等值才算接受），接受时排一次防抖 400ms 的 `converge()`；`settings/document-updated` 总线同样接 `converge`（外部改配置同一口径）。400ms 只做**突发合并**，不承担正确性——正确性由 sync 驱动收敛保证。
2. `converge()` = `call('sync')` → `load()`；sync 失败时把该错误作为 `load` 的 `cause` 上屏（现场照常重读，失败原因不被一次成功的读抹掉）。
3. adapter 建 `writeQueue = createQueue()` 注入 `createDispatch(api, { writeQueue })`，防抖到期的后台对账改为 `writeQueue.enqueue(() => api.sync({}))`。
4. `GroupNav` 记住每行 ref，`selected` 变化时 `scrollIntoView({ block: 'nearest' })`；`doCreateGroup` 只在 `await createGroup()` 返回 true 之后才选中并弹「已创建」。

## 直接后果

- 一次配置编辑突发 = Host 防抖对账 1 次 + 客户端驱动 sync 1 次（同队串行、幂等）；两路不再并发。
- 视图面兑现 AC-04：改配置后自动刷新恰好一次；`↻ 刷新` 退回本职（重查全部上游 + Agent 按修复提示词修完现场后的收敛入口）。
- 「提示成功但对象不在」的两处根因分离：写没落定（toast 现在会闭嘴）与落定了但看不见（现在会滚出来）。
- 新增回归闸 `test/api.test.mjs`「写队列共享」——含装配前的缺陷对照组（对账不入队时读抢跑），删掉注入即红。

## 重访条件

- 幂等 sync 的第二趟成为可感知开销（库规模或目标数增长到 stat 走查明显）→ 改为「写后只重读、由 Host 推收敛完成」并回到 A 案（届时需要 DSH 开放插件自定义事件）。
- 客户端 `converge` 与 Host 防抖窗口在别的机器上出现可感知抖动（编辑后 >1s 才刷新）→ 调窗口或改回读屏障单靠方案。
- DSH 为 settings 写入提供「已接受」回执（含 validate 结果）→ `editConfig` 的快照对比检测可退役，被拒改由回执承载。
