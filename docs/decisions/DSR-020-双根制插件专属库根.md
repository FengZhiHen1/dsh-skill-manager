# DSR-020：双根制——GitHub 外部 skill 迁入插件专属库根

> 状态：已采用（2026-09-06，用户逐项裁定）。修订 DSR-010「目录即库」的单一目录语义：用户目录退化为自研/本地自管区，GitHub 外部条目物理隔离。

## 上下文

DSR-010 的「目录即库」把全部 skill 平铺进用户配置的单一目录：自研/本地与 GitHub 外部条目混居。后果是外部 skill 的物理存续受用户对本地目录的一切整理动作支配（编辑、迁移、改名、清理），`locally_modified` 基线检测防得住"编辑"、防不住"被整体搬走"（2026-09-06 grill-me 手动迁移事故直接促成）：目录没了只剩「缺失」恢复入口，挂载链接悬挂待对账收敛。

用户裁定（同日逐项确认）：外部 skill 不再装进本地目录；现存无外部 skill，**零迁移设计**；同名冲突 GitHub 登记优先+警告；`locally_modified` 检测在专属目录上保留；专属目录位置固定不可配。

## 真实方向与评价

- 方向 A（双根库）：用户根（skillsDir，自研/本地）+ 插件库根（`$DSH_HOME/skill-manager/library`，GitHub 独占）；挂载物化按来源分流源根。与 DSR-017 junction-only 全兼容，改动集中在"源根解析"一处。
- 方向 B（单目录 + 外部条目只读化）：文件系统只读标志挡不住目录级整理（搬走/改名），且 junction 目标只读对用户自研工作流有副作用。否决。
- 方向 C（虚拟化不落地）：DSH/pi 都需要真实目录，排除。

## 最终决定

采用方向 A。

1. **库根固定**：`ctx.dshHomePath('skill-manager', 'library')`，与 backups 同区，不进设置面。
2. **库扫描**：用户根直接子目录 = 自研/本地（不登记）；github 条目由登记表驱动、落插件库根，目录缺失 = `missing` 恢复入口（恢复/更新写入插件库根）。
3. **同名冲突**：用户根目录撞 github 登记名 → 登记优先、本地目录遮蔽（不出列表），冲突名入 `lib.warnings` 出警告条。`add` 撞名检查同覆盖用户根（撞自研目录拒绝入库）。
4. **归属判据双根并集**：realpath 落在用户根 ∪ 插件库根 = 本插件所有；对账摘除、出库摘除、自检重建、行状态走查共用（`inspect.js`/`materialize.js` 同一并集判据）。AC-10 语义不变：改配 skillsDir 只影响用户根前缀，插件库根链接管辖不受改配影响。
5. **源根分流**：物化/走查的源根按条目来源取——github → 插件库根，其余 → 用户根；`service.js` bundle 的 `srcRootOf` 闭包单源承载，纯函数经 `srcRootOf`/`libraryRoot` 参数接收（缺省 = 单根兼容，存量测试零改动）。
6. **locallyModified 保留**：插件库根不是物理禁改，基线对比照常（check/update 的根换为插件库根）。
7. **零迁移**：现存无外部 skill；日后万一出现旧布局（用户根里的 github 目录），其链接按归属判据仍在管辖（用户根在并集内），条目本身按缺失/冲突语义呈现，不做自动搬家。

## 直接后果

- core：`library.js`（双根扫描 + conflicts）、`inspect.js`/`materialize.js`（双根归属并集、srcRootOf 分流）、`reconcile.js`（透传）、`service.js`（libraryRoot 注入、srcRootOf 单源、冲突警告）、`backups.js`（出库双根摘除）、`acquire.js`（撞名覆盖用户根）。
- adapter：`index.js` 注入 `libraryRoot = dshHomePath('skill-manager', 'library')`。
- 契约/UI：overview 形状不变（冲突走既有 `lib.warnings` 通道）；卡片 skillsDir 提示文案更新。
- 文档：本篇 + DSR-010 标注修订 + 需求/挂载与同步/入站操作/目录配置与状态存储/插件运行时相关条目。

## 重访条件

- 出现旧布局存量需要自动搬家时（按 DSR-019 的实测门禁补迁移路径）。
- 插件库根需要可配置（如多 HOME 共享库）时。
