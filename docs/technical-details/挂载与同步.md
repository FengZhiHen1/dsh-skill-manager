# 挂载与同步

## 权威范围

本文唯一拥有 dsh App 语义、DSH 工作区投影、挂载规则推导、junction 物化与摘除、对账流程、行状态走查、Git exclude 维护与挂载失败语义。意图形状（settings 的 `groups`/`skills` 段）与状态域形状归 `目录配置与状态存储.md`，出库摘除与恢复语义归 `入站操作.md`，对账器的触发装配归 `插件运行时.md`。物化与状态面取舍归决策记录 DSR-017（`../decisions/DSR-017-junction-only物化与状态面极简.md`）。

## 结论先行

- 物化只建 junction，失败即报「挂载失败」并附修复提示词，不降级 copy（DSR-017）。
- 归属证明单判据：realpath（悬挂链接以 `readlink` 原始目标兜底）落在当前配置目录内 → 本插件所有。对账摘除、`remove` 摘除与行状态走查三处共用。
- 不变式：本插件在 DSH 全局根与工作区根**只创建/删除 junction，永不创建、修改或删除真实目录**；工作区根中一切非链接内容（C-04 的「既有内容」）一律不触碰，只入行状态与修复提示词。
- 工作区信息现算自 `workspaceRegistry`，不落 storage（无镜像、无归一）；工作区删除后仅报告警告，不删除真实目录（R-12）。

## DSH skill 根与工作区事实

- 全局根：`$DSH_HOME/skills`，由 Host `dshHomePath` 服务解析（`ctx.dshHomePath('skills')`，与 dsh-skill-filesystem 的 `resolveDshHome` 同源；默认即 `~/.dsh/skills`），不得由 `homedir()` 硬编码推导；首次同步时由插件创建。对账/物化/走查一律经注入接收该根；`src/core/mount/derive.js` 的 `globalRoot()` 无参 `~/.dsh/skills` 回退仅为纯函数测试保留，不用于真实物化路径（DSR-015）。测试注入临时根，真实用户根不被测试触碰。
- 项目根：当前 DSH 工作区的 `<workspace.path>/.dsh/skills`。工作区路径由 Host `workspaceRegistry` 给出，已经过 Host 侧规范化。
- 一个工作区项目由稳定 `workspaceId`、当前显示 `title` 与规范化 `path` 组成。挂载规则只持久化 `workspaceId`；`title` 仅供界面显示，重命名不会改变任何挂载键。
- Host 注册表是活动项目唯一来源。Client 的 `ctx.workspaces.list` 只能作为显示状态，不能用来决定文件系统目标或越过 Host 校验。
- DSH 发现逻辑会忽略没有 `SKILL.md` 的目录；配置目录是纯 skill 平铺目录，不含需要隐藏的状态文件（DSR-010）。

## dsh App 语义

- 本插件只管理 DSH 自身的 skill 挂载（需求 R-16）：全局根与当前工作区项目根。不写其他应用的根，历史 `app` 字段已随 `synced` 表一并删除（DSR-017）。

## 工作区投影

每次构建库视图（bundle）前，Host 从 `workspaceRegistry.list()` 取得当前活动工作区，投影为 `{ workspaceId, title, path }`；注册表不可用或返回无效数据（缺 id/路径、重复 id）时以 `workspace-unavailable` 失败，不读写任何项目目录。

- 投影只存在于内存与当次应答，不落 storage（DSR-017）：界面所需的「N 个组使用」按配置意图现算。
- 工作区新建、删除与改名由 DSH 工作区界面完成。技能页不提供注册、改名、改路径或删除项目的写操作；它只允许把分组的挂载目标切换为 DSH 全局或某个当前工作区。
- 工作区从注册表消失后：配置中引用它的挂载规则成为失效引用——推导跳过、不产生期望目标，并在视图警告中报告「未匹配工作区」（R-12 仅报告问题）；其项目根不在扫描范围内，其中的既有链接与目录保持原样，不删除、不修复。

## 挂载推导

输入为配置意图展平（settings 的 `groups` 段展开为 `{group, scope, project}` 挂载规则，`skills` 段给出组归属与禁用标记）与当前工作区投影。形状非法的挂载项跳过（对账容忍）。

输出为 `{ skill -> [target] }`，其中活动 target 为 `{ scope, project }`；项目级 `project` 是 `workspaceId`。参与推导的 skill 集 = 库视图中未禁用且未缺失的条目。

- 一个 skill 的期望位置等于其所属组的全部活动挂载规则；`disabled` 或 `missing` 的 skill 不进入期望集。
- 同名 skill 对同一 target 只保留一条规则。
- 引用不在当前工作区投影中的 `workspaceId` 不产生期望目标，并产生「未匹配工作区」警告。
- dsh 的 target 目录为 `~/.dsh/skills` 或当前工作区 `<path>/.dsh/skills`。

## 归属判据

一个链接是否归本插件所有，只看一件事：realpath 是否落在当前配置目录内——按路径分隔符边界判断，`skills-sibling` 这类共享字符串前缀的兄弟路径不算在内；悬挂链接（目标已不存在）以 `readlink` 原始目标兜底判定。

- 指向库外他处的链接、一切真实目录，均非本插件所有，永不修改或删除（C-04）。
- 改配另一配置目录后，指向旧目录的链接不在新前缀内，自动保留为孤儿，永不清理（AC-10）。
- 该判据由 `src/core/mount/inspect.js` 的 `findOrphanLinks` 单源承载。

## 物化

- 源目录必须含 `SKILL.md`，否则拒绝该 target，防止把无效目录挂进 DSH 根。
- Windows 使用 `fs.symlink(src, dst, 'junction')` 创建 junction；失败不降级 copy，该 target 记「挂载失败」（DSR-017）。
- 目标不存在（空闲）→ 建 junction。
- 目标已是链接：realpath 与源一致为 `ok`；指向库内他处（如改名后的旧链接）按归属判据摘除重建（自检修复）；指向库外的链接非本插件所有，按「挂载失败」报告，不夺取。
- 目标已是真实目录：非本插件所有（本插件永不创建真实目录），按「挂载失败·目标被占用」报告，永不覆盖或删除。

## 对账流程

对账是全量幂等操作，任意活动子项失败不影响其他子项，最终返回 `results/warnings/errors` 三部分。未配置目录时对账与走查不执行，统一返回 `skilldir-unconfigured`。

```text
读取 settings 意图与当前 DSH 工作区投影（storage 两表只供来源与检查缓存，不参与挂载判定）
推导活动期望集
1. 摘除：遍历 dsh 全局根与当前工作区根下的链接；
   归属判据成立（realpath 落在配置目录内）且目标路径不在期望集中 -> 删除该链接
2. 物化活动期望：对每个 (skill, target) 按「物化」节执行，记录 action 或 error
3. 更新当前工作区 .git/info/exclude 托管块
```

- 摘除与孤儿清扫是同一步：归属判据之外没有第二张物化台账（DSR-017），期望之外的自有链接一律摘除，期望之内的保留。
- 自动执行边界（C-04）：对账只执行「空闲目标建链接」与「摘除可证明归属的链接」两类操作；其余一切现场（外来真实目录、指向库外的链接）只记 error 入行状态，交修复提示词流程（R-17）。
- Git exclude 托管块用固定起止标记（`# >>> dsh-skill-manager` / `# <<< dsh-skill-manager`）包裹，内容为项目级 `.dsh/skills/`，防止项目 Git 误提交挂载物；只更新活动工作区，非 Git 项目跳过。托管块是本插件自建标记内容，属 C-04 允许范围。
- 触发路径：Client 显式 `sync`；配置变更经对账器 200ms 防抖触发；`add/update/restore` 等写操作收尾触发（装配归 `插件运行时.md`）；库工具条「刷新」附带触发一次（语义归 `插件运行时.md`）。

## 行状态走查

走查只读，不修改任何文件；与对账共用期望推导与扫描原语，结果为库视图每个 skill 行的挂载状态（R-03：挂载问题以行状态呈现，无独立健康视图）。

每个期望目标判定其一：

| 目标状态 | 判定 | 行呈现 |
|---|---|---|
| `ok` | 链接存在且 realpath 指向对应源 | 无徽章（正常） |
| `link-missing` | 期望位置不存在（对账后仍缺失，如目标根不可写） | `挂载失败` |
| `target-occupied` | 期望位置是真实目录（含旧版本遗留 copy） | `挂载失败` |
| `wrong-target` | 期望位置是指向库外的链接 | `挂载失败` |

- 行级状态另有：`missing`（github 条目目录缺失）、`disabled`（已禁用）、`no-skill-md`、名文法风险（安装名不满足 C-01 文法，DSH 不可见）；外部 skill 的检查状态（`可更新`/`已是最新`/`检查失败`/`本地有修改`）来自检查缓存，不走查。
- 非行级警告：「未匹配工作区」引用与其他推导警告，在管理视图顶部提示条呈现。
- 期望之外的自有链接（孤儿）由对账摘除，不构成行状态。
- 遮蔽事实：项目级 `.dsh/skills` 的合并 rank 高于用户级 `~/.dsh/skills`；工作区根存在同名真实目录时该项目内以本地版为准。该目标同时按上表报告 `target-occupied`，行状态与修复提示词已覆盖提示职责，不单设遮蔽状态。

## 失败语义

| 失败 | 结果 |
|---|---|
| 源缺 `SKILL.md` | 该 target 记 error，其他 target 继续 |
| 目标是真实目录或指向库外的链接 | 记 error（行状态「挂载失败」），不修改、不覆盖 |
| junction 创建失败 | 记 error，附修复提示词（如目标卷不支持 junction 的说明） |
| 工作区注册表不可用 | 返回 `workspace-unavailable`，不读写任何项目目录 |
| workspaceId 不在当前投影 | 配置中的失效引用由推导跳过并报告「未匹配工作区」警告 |

## 验证边界

- 验证用项目通过 DSH 工作区创建或选取；其 `.dsh/skills` 可证明项目级 DSH 根约定成立。
- 覆盖工作区创建、改名、删除与失效引用警告四类场景。
- 全局首次同步必须自动创建 `~/.dsh/skills`，不要求用户手工建目录。
- 新建会话可见性、当前会话 watcher 即时性与 junction 是否被 watcher 识别为目录变化，按需求验收实测并记录结果。
- 既有内容零触碰按 AC-13 与 C-04 构造现场验证：外来真实目录、指向库外的链接、空目录在执行任何操作（含对账）后内容与元数据不变。
