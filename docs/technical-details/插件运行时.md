# 插件运行时

## 权威范围

本文唯一拥有 `dsh-skill-manager` 的包形态、组合挂载与部署、Host 服务与 RPC 传输（DSR-014）、请求调度与缓存、配置读写机制（配置即意图）、错误与修复提示词呈现（DSR-018）、Client 设置页与生命周期。意图与状态的存储形状归 `目录配置与状态存储.md`，业务操作语义归 `入站操作.md` 与 `挂载与同步.md`，技术选型归 `../技术栈设计.md`，部署取舍归 DSR-012（`../decisions/DSR-012-部署通道迁移.md`）。模块划分归 `../项目结构设计.md`（DSR-015/017）。

## 平面划分

本插件没有模型可见工具或 Skill provider，按 Host/Client 两棵树划分：

| 平面 | 职责 | 不承担 |
|---|---|---|
| Host | settings 命名空间注册、目录门禁、storage 域读写、DSH 工作区投影、网络、三路调度队列、`connection.rpc` channel `/skill-manager`、配置对账器、修复提示词 facts 生成 | 注册模型工具、贡献 Prompt |
| Client | `settings.section`、两视图、Plugins 页配置页（官方 `SettingsForm` 原语）、`configForms` 直读直写、数据加载与错误呈现、修复提示词模板组装与复制 | 本地持久化、直接写配置目录、手工注册项目 |

部署形态为全局可用型：Bundle 挂载 Host 行，Client 随页面启动加载一次；设置页不依赖当前会话。

```json
  },
  "engines": { "node": "^22.19.0 || >=24" },
  "files": ["src/", "dist/", "cordis.patch.yml"],
  "dependencies": {
    "zod": "^3.25.0"
  },
  "peerDependencies": {
    "@deepseek-ai/dsh-storage-domain": "^0.1.7-rc.2",
    "@deepseek-ai/schemastery": "^3.18.4"
  },
  "dsh": {
    "bundle": { "patch": "./cordis.patch.yml" },
    "client": {
      "platform": "web",
      "inject": [
        "@deepseek-ai/dsh-client-connection",

        "@deepseek-ai/dsh-client-ui-primitives",
        "@deepseek-ai/dsh-client-ui-settings",
        "@deepseek-ai/dsh-client-ui-plugin-manager"
      ]
    }
  }
}
```

- `dsh.bundle.patch` 使包进入 reconcile 的 bundle 通道：安装后自动进入 `dsh.profile.bundles`，patch 随之应用（DSR-012）。
- `dsh.client` 是 Client 被发现的前提；声明了就必须有 `exports["./client"]`（指向 esbuild 产物 `dist/client.js`，DSR-016）。`inject` 边是**信息性**的（加载/预取元数据，不决定激活顺序），指向不存在的包**静默跳过**——故它是类型与打包期问题，运行期不炸，但也别指望它做校验。
- 运行时依赖（DSR-025 重排）：**`@deepseek-ai/schemastery` 从 `dependencies` 上移到 `peerDependencies` + 同版本 `devDependencies`**。理由是解析路径：一般模块导入**先按 importer 的 Node 搜索路径取物理候选，未命中才进运行时拦截**，所以 `dependencies` 里那份物理副本会把插件钉在旧 schemastery 上——`3.18.2` 及更早**没有 `.volatile()`**（实测 0 命中），`Config` 会在 import 期直接抛 TypeError。改 `@deepseek-ai/` 前缀后本包树内无物理候选，落到平台运行时那份 3.18.4。`devDependencies` 供裸 node 单测解析；profile 侧 `autoInstallPeers: false` 不会装回副本。
- 两个 `@deepseek-ai/dsh*` peer 同时是**版本门禁的载体**：peer 范围不满足运行中的 DSH 版本时整行被自动置 `disabled: true`、插件根本不加载（实例照常启动，只在 stderr 留一行）。判定语义 `semver.satisfies(rt, range, { includePrerelease: true })`。⇒ **`0.1.7-rc.2` 以下运行时上本插件整行不加载**，升级顺序必须「先升实例、再挂/更新插件」。
- `zod` 仍是普通 `dependencies`（storage 域表记录校验，DSR-010）；ZIP 解包用自研零依赖读取器（`src/core/base/zip.js`，基于 `node:zlib`，只读 store/deflate 与单卷 ZIP），不引入 fflate——免去安装链。若未来需要 zip64/加密/分卷再换库。
- Host 半区无构建（`src/` 下 `.js` 即交付）；Client 半区产物提交入库，`check` 脚本含产物新鲜度哨兵（DSR-016）。

## Host 入口

- 导出形态：`src/adapter/index.js` 默认导出 `{ name: 'skill-manager', inject: [...], Config, apply(ctx, config) {...} }`，`apply` 同步完成注册，异步设施（storage 域、迁移）在后台就绪。
  - **`Config` 必须挂在 default 对象上**：loader 读的是 `plugin.Config`（`vendor/cordis/src/registry.ts:326`），而它取插件模块走 `unwrapExports` 的 `exports.default ?? exports` —— 对象式形态下具名 `export const Config` **到不了**那里，丢了 Config 的后果是本行静默失去 schema（无默认值、也不上设置页）。
  - `apply` 的第二个参数是 loader 按 `Config` 校验并填默认后的配置，**不是**原始补丁值；见「配置即意图」。
- 硬依赖 `inject: ['connection', 'workspaceRegistry', 'storage', 'dshHomePath', 'settings']`（DSR-014 起移除 `webServer` 与 `loader`）：
  - `connection`：注册 RPC channel `/skill-manager`（`ctx.connection.rpc.handle`，围栏由平台逐请求应用，注册 fiber-scoped 随卸载自动摘除）。
  - `workspaceRegistry`：活动工作区唯一来源；每次构建库视图时读取其实体的稳定 id、当前 title 与规范化 path，现算工作区投影（不落 storage，DSR-017）。
  - `storage`：域设施（`ctx.storage.domain.open(spec)`，域在 fiber 结算后异步打开、Fiber 清理时关闭；打开失败只降级 API 为 `internal`，不拖垮 Host）。
  - `dshHomePath`：定位 `$DSH_HOME`（备份树根 `skill-manager/backups`、全局 skill 根 `skills`）。
  - `settings`：页面策略与写面（`ctx.settings.configure` / `ctx.settings.update`）。⚠ **0.1.7 起它不再是配置读面**——配置真相在 `apply` 的 `config` 参数里，`ctx.settings.register` 与 `SettingsScope` 在新树零命中。
- adapter 四文件分工（模块边界归 `../项目结构设计.md`）：`index.js` 入口装配、`settings.js` 配置边界（`Config` schema + volatile 读取 + 校验挂点）、`storage.js` spec 与开域、`migrate.js` 迁移编排；全部领域逻辑在 `src/core/`。
- `apply` 内装配模块实例，所有可变状态（域句柄、队列、缓存、定时器）放在本次 Fiber 的局部对象中，不使用模块级可变单例。
- 配置边界（`adapter/settings.js`，schema 形状与跨字段校验来自 `core/model/intent.js`）：见「配置即意图」。旧 storage 意图的一次性迁移（`adapter/migrate.js`）**等本 fiber 结算后**先于新域打开执行，失败仅告警（语义归 `目录配置与状态存储.md`）。
- 目录解析：每次 RPC 从 volatile 引用**现读**当前 `skillsDir`（pi 开关同频现算，pi 目录固定默认路径探测，DSR-019），不做启动缓存；为空时所有方法统一返回 `skilldir-unconfigured`，不访问任何目录路径。双根制（DSR-020）：插件库根 = `$DSH_HOME/skill-manager/library`（`dshHomePath` 注入，固定不可配），GitHub 条目的入库/更新/出库/基线检查全部落在插件库根，物化与走查按条目来源分流源根（github→库根，其余→配置目录）。
- 通道注册：`ctx.connection.rpc.handle('/skill-manager', (endpoint, payload) => service.dispatch(endpoint, payload))`（`adapter/index.js` 内联）；平台对每个请求先应用围栏（见「RPC 传输」），handler 内不再做防伪。
- 对账器：`ctx.on('loader/volatile-update', …)` 监听本行配置变更 → 200ms 防抖 → `sync` 对账（意图展平 → 摘除/物化文件系统 → 预热缓存）；对账失败只记日志并反映在行状态，不打断配置编辑。
- 启动预热：`apply` 后延迟 1s 后台调用 `warm`，配置了目录时首次打开设置页秒出。
- 异常边界：`service.dispatch` 捕获所有错误并按 Result 信封返回（不抛出）；未捕获异常只记录日志，不冒泡杀死 Host。

## 请求调度与缓存（低延迟路径，DSR-013）

调度策略收在 core `service.js` 的 `dispatch`（DSR-015 起从入口函数迁入；队列与读屏障是 R-13 一致性语义的一部分，属于领域而非传输）。三类分流：

1. **读方法**（`overview`/`warm`/`backups`）**不排队**，直接读进程内 bundle 缓存快照；写操作进行中（`writeQueue.busy`）时读请求先等写屏障结算，避免冷扫读到半写状态。
2. **文件写方法**（`add`/`update`/`remove`/`restore`/`sync`）FIFO 串行（R-13 写写互斥）；每个写方法收尾 `refreshCache()` 重算并预热缓存，失败不掩盖写结果（清缓存由下次读冷扫兜底）。
3. **网络慢方法**（`check`/`search`/`repo-skills`）独立队列，绝不阻塞读写——zipball 下载最长 90s 不再拖住任何列表刷新。

缓存层（`src/core/base/cache.js`，全部以配置目录为事实边界）：

| 缓存 | 键与失效 | 用途 |
|---|---|---|
| bundle 快照 | 配置目录 root + 约 800ms TTL + 单飞冷扫；写后 `refreshCache` 预热 | overview/warm 共享的库快照（扫描项、组文档、挂载意图、工作区投影、行状态）；缓存热时读请求零扫描零存储读 |
| meta 缓存 | `${root}\0${dir}` + SKILL.md 的 stat 签名（`mtimeMs:size`） | 重扫退化为 N 次 stat，签名一致即复用 frontmatter 解析结果 |
| hash 缓存 | 目录 + 5s TTL；写操作统一清空 | `check` 的展示性本地修改判定；`update` 的破坏性判定强制 `fresh` 重算 |
| 行状态代际 | 随 bundle 引用失效 | 同一快照内复用文件系统走查结果 |

一致性：读全部返回同一冻结快照引用（永不撕裂）；写操作串行且缓存只在写完成后更新；配置目录变更 → 缓存键（root）失配 → 自动冷扫。

## RPC 传输（DSR-014）

- 通道：官方通用 RPC（`connection.rpc`，知识库 `client/17`）。Host 侧 `ctx.connection.rpc.handle('/skill-manager', handler)`（`adapter/rpc.js`，注册 fiber-scoped、卸载自动摘除）；Client 侧 `ctx.connection.rpc.call('/skill-manager', method, payload)`。方法名即 endpoint（`POST /skill-manager/<method>`）；平台校验信封、端点与 `Content-Type`（非 JSON 415、非法信封 400、方法 ≠ endpoint 拒绝）。
- 围栏与认证由平台承载，插件不再自携带（旧 `lib/fence.js` 删除）：每个请求先过 `isTrustedApiRequest`（Host 头回环或 connection 行 `trustedHosts`；拒绝 `sec-fetch-site: cross-site`；带 `origin` 时其 host 必须与请求 host 一致）——与旧 fence 同一算法，部署运行时 `0.1.1-rc.2` 实证等价；alpha.3 起平台在围栏之后追加 browser-auth（process token/cookie，未认证 401）。被围栏/认证拒绝的请求不进 handler。
- 方法结果（平台 `result` 字段）为传输中立 Result，由 core `service.js` 产出：

```json
{ "ok": true, "value": {} }
```

```json
{ "ok": false, "error": { "code": "name-conflict", "message": "skills/pdf 已存在", "details": { "retryable": false, "repair": {} } } }
```

- 错误映射（`service.js`）：`SkillManagerError` → `code`/`message` 原样、`details.retryable` 取错误标记、`details.repair` 取修复 facts（见下）；`GhError` 网络分类 → `code` = `kind`，`retryable` 仅 `unreachable`/`rate-limited` 为 `true`；`ContractError`（出站载荷校验违例）→ `code: "contract-violation"`；未分类异常 → `code: "internal"`（不冒泡杀死 Host，附通用 repair 模板）。`update` 的 `local-changes-confirmation-required` 等稳定 code 不变。
- 修复 facts（DSR-018）：core 按错误码的元数据表生成 `repair = { operation, summary, facts: [{ label, value }], recommendation: [...] }`——`summary` 与 `recommendation` 按 code 取模板，抛出点携带动态 facts（操作名、相关路径、配置快照）；Client 用统一模板组装完整提示词并提供一键复制。任何失败（含 `internal`）都必须携带 `repair`。
- 方法清单（配置读写不在此层——意图经 settings 域直读直写，见「配置即意图」）：

| 方法 | 主要 payload | value 摘要 |
|---|---|---|
| `overview` | 无 | 只读视图（低延迟路径）：`{ root, lib, workspaces, agents, warnings }`；`lib.skills` 每项含意图叠加（disabled/group）、挂载目标推导（targets，`host:scope|project` 键）、行状态（status，含 `mount` 失败明细）与上游检查缓存（upstream）；`lib` 附检查时间 `checkedAt`；`workspaces` 为当前工作区投影（含「N 个组使用」计数）；`agents.pi` = pi 接管可用性（`available`/`skillsRoot`，DSR-019）；`warnings` 含未匹配工作区引用与 pi 不可用等非行级警告；`root` = 配置目录绝对路径（供修复提示词） |
| `warm` | 无 | 启动预热（只读）：预热 bundle 扫描与行状态缓存 |
| `search` | `query, limit, offset` | `query, count, skills` |
| `repo-skills` | `repo, ref` | `repo, branch, commit, candidates, via` |
| `add` | `repo, dir, ref, as` | `name, repo, branch, commit, sync` |
| `check` | `names?` | 结果数组；并行探测（同 repo 同分支去重），合并写入检查缓存（DSR-008） |
| `update` | `names?, confirmLocalChanges?` | `{ results, sync }`；检测到本地修改而未确认时返回 `local-changes-confirmation-required` |
| `backups` | 无 | 备份数组（`id, name, time, has_meta`） |
| `restore` | `id` | `name, sync` |
| `remove` | `name` | `name, backup, detached` |
| `sync` | 无 | `{ results, warnings, errors }` |

- `update` 的本地修改确认由 Host 强制执行（语义归 `入站操作.md`）：未携带 `confirmLocalChanges: true` 时不得下载或覆盖；Client 的遮罩确认只是该安全边界的交互入口。
- 未配置目录时所有方法统一返回 `code: "skilldir-unconfigured"`、`retryable: false`（含 search/repo-skills，避免"可搜不可落"的半可用状态），消息提示先到设置「插件」区配置「本地 skill 目录」。
- 配置的目录缺失/不可访问时，所有方法统一返回 `code: "skilldir-missing"`、`retryable: false`；插件保持存活，不阻塞启动。

## 配置即意图（核心模型，DSR-011；挂点换代见 DSR-025）

- 用户意图的唯一事实源是 **本行 loader entry 的 Cordis `Config`**，持久化在该 profile 的 `cordis.patch.yml` 行 `config` 里（0.1.7 模型：旧「settings.yaml 的 `skill-manager` 段 + settings 文件提供方」整体作废）。字段形状归 `目录配置与状态存储.md`。
  - ⚠ **命名空间就是行 id**，且**是本插件的 loader entry id**（`cordis.patch.yml` 的 `id: skill-manager`，与包名 `dsh-skill-manager` 无关）。settings 面按 `entry.options.id` 建 ns；写错 id 会撞 `No configurable plugin entry`。改行 id 而不改 `CONFIG_NS` = 配置页与命名空间静默解绑。
  - ⚠ 运行期 Loader entry id 是 **`include:skill-manager`**（profile 行都在 bootstrap include 树里，会被加前缀）；命名空间用**不加前缀**的那个。
- **注册即声明**：`Config` 里每个字段都带 `.volatile()`（`configSchema(z)` 在 `core/model/intent.js`，实例由 adapter 注入——core 不得 import `@deepseek-ai/*`，分层门禁 R1）。只有 volatile 字段可写、且写入经「替换引用快照」提交进**运行中**的 fiber（不重挂载）；非 volatile 字段既不上设置页、写它直接抛 `Config field "x" is not volatile`。⇒ 漏标 `.volatile()` 是静默功能缺失。
  - volatile 字段的运行期值是**只有 `get()` 的冻结引用**；`readConfig()` 每次调用现读解包，于是「改完立即生效」不依赖任何 watch 回调——这正是旧代 `scope.watch` 要做的事在新模型下的消失方式。
  - 摆放有硬约束：volatile 必须落在**固定对象路径**上（不允许 volatile 套 dict/union 子项、不允许 volatile 嵌 volatile），违规在**解析期**（schema 调用时）抛 `volatile fields require a fixed object path`。本插件五个顶层字段各标一次，测试锁住该不变量。
- UI（技能页与 Plugins 页配置入口）经 **`ctx.configForms.get('skill-manager')`** 直读直写：`ConfigForm` 与旧 `SettingsScope` 逐方法对应（`getSnapshot()` 的 `value`/`user` 层、`subscribe`、`set`/`unset`/`mutate`），底层走 `settings.describe`/`mutate`。旧 `ctx.settingsScope.bind({ namespace })` 在新树零命中。
- 渲染即时（表单镜像页面启动即加载）、保存即生效；写入未落定时由客户端**以 Host 权威值裁定**（`writeVerdict`：写后另读一次 `settings.describe` 取该字段解析值——等值 = accepted、不等 = not-applied、读不到 = unknown），裁定结果连同修复提示词复制入口一起上屏（DSR-018/DSR-024）。**没有任何自定义配置写协议**。
  - 0.1.7 又添一条同向理由：`internal/config` 拒绝的候选由 loader 记 warn 并**保留原引用**，而 profile patch 此时已落盘——正是「持久层已写、运行期未生效」，只有权威读能抓到。
- 跨字段校验（`skillsDir` 绝对性、组名合法性、空 `hosts` 死规则）挂在两处：`apply` 内对**已解析**配置校验（非法即让行挂载失败，响亮）；`ctx.on('internal/config')` waterfall 拦设置页写入的候选（抛错 → 写路径拒绝、不落盘）。`.check()` 这类 schema 级钩子**在本基线不存在**（仅上游文档提到，源码零命中）。
  - waterfall 拿到的是**原始** config（`!!js` 表达式尚未求值，`interpolate` 在其之后），故该校验对表达式占位对象一律跳过（`isOpaque`）——旧代 `validate` 作用在已解析值上，这是本次迁移引入的差异，已在测试中钉住。
- 配置写是字段级原子；引用完整性（组/工作区是否存在）由对账层容忍回落（推导跳过失效引用并警告），跨字段编辑的中间态必须放行。
- storage 域只存运行时投影（入库元数据与检查缓存两表）；旧七表意图由一次性迁移投影进配置行（语义归 `目录配置与状态存储.md`）。
- 本地 skill 无版本管理：自有目录不登记 storage；`disable/enable` 归配置，无独立端点。
- 任何文件/网络变更方法成功后的 `value` 只返回该操作结果；Client 随后重取 `overview`（命中写后预热缓存，零扫描）。

## Client 入口

- 源码 `src/client/`（JSX 多文件，DSR-016），esbuild 产单文件 `dist/client.js`：惰性 CommonJS 工厂闭包，由 `window.__ModuleLoader__.load({ id: 'dsh-skill-manager', factory })` 包裹，导出 `{ inject, apply }`；`inject: ['slots', 'workspaces', 'uiWorkspace', 'configForms', 'remote', 'remote.settings', 'connection']`（`remote.settings` 是写后裁定权威读的硬依赖——客户端 remote 命名空间按 traced service 暴露，**取属性前必须在 inject 里声明**，否则运行时抛 `cannot get property "remote.settings" without inject`；与一方 Client 插件同一约定）。产物提交进 git；修改源码后须重建产物（`check` 脚本哨兵保证新鲜度），已挂载包的 client 产物更新刷新页面即生效（无需重启）。
- 运行时外部依赖只有 `react`、`react-dom` 与 `dsh.client.inject` 声明的 `@deepseek-ai/dsh-client-*` 包（含 `dsh-client-connection`，DSR-014；`dsh-client-ui-settings` 提供 `configForms`，`dsh-client-ui-plugin-manager` 拥有 `plugins.*` 槽族）；esbuild 外化集合与该声明一致。
- Client `apply` 的核心注册：

```text
const scope = ctx.configForms.get('skill-manager')

slots.inject('settings.section', () =>
  slots.register(
    { name: 'settings.section', id: 'skills', order: 16, label: '技能', inject: () => ({ call, workspaces, scope, subscribeSkillSettings, readConfigField }) },
    SkillsSection
  )
)
// 期望目标槽由 ui-plugin-manager 声明，故用 slots.inject 等声明就绪；
// 只在 Host 服务该命名空间期间注册（未挂本行的 profile 不留痕迹）。
configForms.whileServed(['skill-manager'], () =>
  slots.inject('plugins.row.config', () =>
    slots.register(
      { name: 'plugins.row.config', key: 'dsh-skill-manager#skill-manager', inject: () => ({ scope, uiWorkspace, readConfigField }) },
      SkillManagerCard
    )
  )
)
```

- `settings.section` 注册 `id=skills`、`order=16`、中文标签 `技能`；本插件只使用页面渲染区，不扩展设置导航之外区域。
- **配置页接线（0.1.7，取代已废的 `settings.plugin.item` 卡片；外观与交互见 DSR-026）**：本行配置挂在侧栏 **Plugins 页**，槽位 `plugins.row.config`（keyed，key = `<包名>#<行 id>`）。组件按 `view` 分发：`'summary'` 只回一句话（行缺描述时作其回落），`'page'` 才是表单主体。页面另会下发一次性 `form` prop（`{state, mutate}` 快照），本插件**不用它**——可观察源是 `hooks` 舱里的快照 store（渲染器合成 `useConfigPage` selector hook），才有实时重渲染能力。
- **表单用官方原语，不自绘**（DSR-026）：`<SettingsForm labels state onSave onDiscard>` 包一个 `SettingsValueField`（skillsDir）与一行自绘的 pi 复选框。草稿暂存、revision 围栏、保存后回读、**离开页面丢弃**全归 `SettingsFormModel`（`src/client/config-page.js` 的 `ConfigPageController` 逐段镜像官方 `ShellCardController`）。⇒ 没有「放弃」控件、没有「未保存」标记（官方语义，`SettingsForm.tsx` 原文 discards on unmount and offers no discard control）。字段规格下沉到浏览器安全的 `core/model/page-specs.js`（`skillsDirSpec`/`piSpec`），字段名与 schema 的**同键**由 `test/page-specs.test.mjs` 机械钉住。
- 数据源：挂载时经 `configForms` 快照直读配置（渲染即时，永不等待网络）；列表/行状态/工作区投影来自单次 `overview`（缓存热时零扫描）。管理与搜索两视图从配置 + 库元数据派生：管理视图的 origin/group/q 过滤为纯前端本地过滤（零请求）；禁用/分组/挂载开关等配置操作 = `scope.set('groups'|'skills', next)` 整字段替换（本地即时生效，Host 对账器后台收敛）；写入未落定（裁定 ≠ accepted）时按裁定上屏原因 + 修复提示词复制入口（含配置目录路径、字段、尝试值/权威值、排查方向，DSR-018）。**裁定不拿镜像快照做**：共享表单只把「最新一笔写」的回执折进镜像，被后续写超越的那一笔镜像永远落后，按它比对会把已经落盘的写误报成「被拒绝，已恢复原值」（2026-09-14 现场实证，DSR-024）；`add/update/remove/restore/check` 等非配置操作仍是请求-响应。不写 `localStorage` 或 IndexedDB。
- **写后自动收敛刷新（DSR-021，2026-09-09）**：配置写被权威快照接受后，`editConfig` 排一次 400ms 防抖的 `converge`——先 `call('sync')` 驱动 Host 收敛（经写队列串行，返回即现场已按当前意图收敛并预热 bundle 缓存），再重读 `overview`；一次编辑突发（组改名连写两字段）合并为一次刷新。Host 侧 `loader/volatile-update` 的 200ms 防抖对账与 RPC 写共用同一条 WRITE FIFO（`createDispatch(api, { writeQueue })` 注入），不再自起一路——并发对账会对同一目标重复建链（后到者吃 `EEXIST` 误报挂载失败），且不入队的对账不被读屏障看见。`settings/document-updated` 总线（配置页保存/重置 `skillsDir`、外部手改 profile patch）也接 `converge`，口径一致。
- 修复提示词统一组件（DSR-018）：输入为 Host 下发的 `repair` facts 或配置写入裁定的本地上下文（`not-applied` = 权威值未变、`unknown` = 读不到权威值，两态各自措辞，只陈述裁定事实、不自称"Host 降级拒绝"），按单一模板组装完整提示词（插件与操作背景、错误码与消息、上下文清单、推荐处理方案、只读红线提醒），提供一键复制；RPC 操作失败、配置写入未落定、行状态「挂载失败」徽章点击展开三处呈现面共用。
- 配置页：注册 `{ name: 'plugins.row.config', key: 'dsh-skill-manager#skill-manager' }`，注入面 = `{ ...page.inject(), uiWorkspace }`（`page.inject()` 给 `hooks.configPage` 与官方模型的 `edit`/`resetField`/`save`/`discard`）。**不再注入 `readConfigField`**（DSR-026）：两字段进同一次原子 mutate，卡内不存在「连发两笔写、第一笔读到落后快照」的窗口（DSR-024 的成因），且官方模型保存后自会回读并判定未落定；技能页的 `groups`+`skills` 两步写仍需它。字段经官方 `SettingsValueField` 渲染（自带 label/hint/「已覆盖」/「重置」/非法文案槽位）；pi 是布尔，官方只有 number/text 两个 spec 助手，故复选框自绘（官方页对布尔同样自绘），但勾选只暂存、保存才落。「选择…」按钮经 `uiWorkspace.pickDirectory()` 调 Host 原生目录选择器（`pickDirectory` 属 `uiWorkspace` UI 域服务面；`workspaces` 是 Workspace Controller 管理面，其上没有 picker——0.1.2-rc.1 实测 `workspaces.pickDirectory is not a function` 为证）（File System Access API 不暴露绝对路径，故不用浏览器 API）。保存未落定时在 children 里补一个可复制的修复提示词（官方表单只给一句 `saveFailed` 文案、不透明原因）。
- 未配置状态：技能页经 `configForms` 快照判定 `skillsDir` 为空 → 直接显示未配置引导（**不等 overview**，配置渲染零网络）；配置页始终可用，是进入配置的唯一入口。
- 样式 token（DSR-026）：色值走 `--dsw-alias-*`，**半径走 `--dsw-radius-*` 六档**（`theme.js` 的 `R`：控件/小件 → `sm`，面/容器 → `md`，大浮层 → `lg`；整圆胶囊与状态点保持 `999`/`50%`，与官方 `Tag`/`Switch` 一致），浮层阴影走 `--dsw-elevation-panel`/`-prominent`，遮罩走 `--dsw-alias-bg-mask-1`。⚠ 宿主的半径守卫只扫它自己仓内 CSS，**不约束第三方内联样式**——归位是为与外壳共用同一套材料，不是兼容性要求。
- 设置导航图标补丁：宿主设置外壳的 `navIcon(id)` 是**封闭清单**且 `settings.section` 没有 icon 字段，「技能」会落到默认齿轮与「通用」撞图标；Client 用 MutationObserver 找到本插件导航行，就地改写其 svg 子节点。**0.1.7 图标体系整体换代**（size-neutral 命名 + 重绘几何，旧 75 个带尺寸后缀的导出全灭），故手抄的 path 数据同步换成宿主 `IconSkillOutlineRegular/Medium` 的现行几何（weight 取 Medium：决策笔记把「导航图标」列为该 weight 的既定用途），viewBox 与描边宽度一并同步。宿主 DOM 结构变化导致找不到目标时静默保持原图标，不影响任何功能。
- 样式：对齐 DSH 原生——主题 token 用 `--dsw-alias-*` 系列（ui-theme 定义），按钮/输入/徽章复用 ui-primitives 的 `Button`/`Input`/`Pill` 原子组件，状态色用 `--dsw-alias-state-*-primary` token + `color-mix` 透明晕；不注入全局样式表。
- **页边距归外壳所有（2026-09-09 走查修复）**：设置页外壳 `.options` 自带 `padding: 0 24px 24px`，官方各节（通用/插件/模型）的 section 根组件**一律不再自加横向内缩**；本插件技能页曾自加 12px（页头 `4px 12px 0`、页签条 `0 12px`、视图根 `S.panel: 10px 12px`），使内容左右各窄 12px 且整列右移——表现为「与标准标签页页边距不一致」。现行口径：页头/页签/视图容器/页级错误条横向零内缩，`S.panel = 10px 0`。页签几何同 `PluginsSettingsSection`：标题 18/600、副标题 13 tertiary、`gap: 22`、页签 `7px 1px 9px` 13/20px、分隔线 `0.5px solid var(--dsw-alias-border-l2)`、激活态只加 2px 下划线不改字重。卡片与行内 padding 属组件内部几何，不受此约束。
- 卸载：`slots.register` 返回的 disposer 进入 Fiber effect；组件内定时器、abort 控制器与 MutationObserver 在卸载时清理。

## 视图设计

设置页为两视图（管理、搜索）+ 库工具条（R-11）。本插件不再维护独立设计稿：本节只承载交互语义与信息架构，视觉与交互细节以设置页实际实现为准。

### 管理视图

- 信息层级：主从两段式——左栏分组导航（纵列、计数随行、列随主从行拉伸等高、仅超出可用高度才内滚，容纳无上限分组；「＋ 新建」收进栏头），右栏为当前组的范围卡与技能库（DSR-009 演进：分组胶囊行在工作区与分组无上限场景下失效，2026-09-06 重构）。选中「全部」时范围卡位置换为提示卡，技能库列全部技能。
- 新建分组：点按 chip 打开模态对话框（与更新确认同一遮罩语言），输入组名并提示「新组复制『默认』组的挂载规则作为起步（不含 DSH 全局，全局需显式勾选）；组名 1–30 字符」；创建成功后选中该组便于立即配置范围（DSR-009）。客户端预检长度与保留字，完整规则由 Host validate 兜底。**起步模板不继承 `global` 作用域**（2026-09-09 口径）：挂 DSH 全局对该 HOME 的所有会话生效，只能由用户显式勾选；项目级规则仍照抄默认组。**成功话术只跟写落定**：`config.createGroup` 返回 `Promise<boolean>`，`doCreateGroup` `await` 到 true 才选中 + 弹 toast；被拒/传输失败时错误条已上屏，不再谎报「已创建」（2026-09-09 走查：toast 说成功、列表里找不到该组）。
- **选中组滚入视野（2026-09-09 走查修复）**：新建/切换的组落在折线以下时呈现为「组里没有」——`GroupNav` 记每行 ref，`selected` 变化时 `scrollIntoView({ block: 'nearest' })`；`nearest` 保证已在视野内时页面不跳。列高形态修订（2026-09-10 走查，取代 DSR-021 的「保留 `maxHeight: 320` 封顶」案）：定高封顶在右栏很长时左下大片空白仍逼出滚轮，违反直觉；改为左栏随行 `stretch`、列表 `flex: 1; minHeight: 0; overflowY: auto`——行高取两栏较高者，正常情况下分组全量直显、无内滚。
- 改名/删除：入口收进「当前分组」卡标题行的 ⋯ 菜单（DSR-009）；改名点按后标题行变内联编辑态（输入 + 保存/取消，Enter/Esc 快捷），成员与挂载规则同步改名；**两字段写串行**（`await editConfig('groups', ...)` 落定后才写 `skills`，第一笔未落定即中止）——并发写会留下"组名没改成、成员却已指向新名"的半套用（成员按失效组回落「默认」，挂载静默丢失，DSR-024）；**视图切换只跟写落定**：改名/删除被接受才切分组筛选（未生效时留在原组，避免筛选跳到并不存在的组名，2026-09-14 走查）；删除二次确认并提示成员回落默认组；「默认」为虚拟组，不出现入口。
- 分组项目配置：使用范围将每个活动 DSH 工作区作为可选目标；切换直接编辑 settings 配置，不提供项目注册或路径编辑。全局目标与工作区目标用同一复选行组件呈现（hover 浅底、勾选态品牌色晕、复选框 `accent-color` 品牌色）。**工作区两区收纳（2026-09-06）**：已勾选常显，未勾选收进「▸ 展开其他 N 个工作区」虚线条；工作区数 >8 出过滤框（过滤中平铺全部匹配项）；列表区为描边内嵌滚动面板（7 行封顶内滚），卡片高度不随工作区数增长。**宿主 chips（DSR-019）**：行勾选且 pi 可用时行尾出 `[DSH][pi]` 切换 pill（点按不触发行复选框），勾选 pi 即同组同步物化两侧；关掉最后一个宿主等效取消整行。**取消防御（2026-09-05 走查事故）**：取消勾选时若该组在该目标下存在链接（移除数 >0，跨 dsh/pi 双侧计，按与 Host 同源的失效组回落口径从 `overview.targets` 计算），必须先经遮罩确认对话框明示目标与移除数量（与更新确认同一对话框语言，强调只删链接指针、文件不动、重新勾选可恢复）；移除数为 0 直接写入不打扰。
- 组名防撞（同批防御）：`groups` 字段为全量覆盖写，新建撞既有组名、改名撞目标组名都会静默覆盖对方规则——客户端在写入前拒绝并上错误条（Host validate 不校验 map 键覆盖），拒绝时不得继续走"成功"路径（不假装创建/改名成功）。
- 库工具条：搜索过滤、来源筛选、`↻ 刷新`（重新检查全部上游、执行一次安全对账并刷新列表——Agent 按修复提示词修完现场后的收敛入口，DSR-008/017）。配置变更**不需要**点它：写后自动收敛刷新一次（DSR-021），`↻ 刷新` 只承担「重查上游」与「人工修完现场后强制收敛」两件事。
- 行信息含名称与 meta 行（来源 · 上游 commit 短指纹；仅「全部」视图追加分组与生效位置——分组视图下右栏已收窄，逐行重复是噪音），描述作为悬停提示；行为单容器卡 + 分隔线的高密度列表（非逐行描边卡）。
- 页签为文字页签（激活下划线），每页一句副标题；视觉基元统一为：白底描边卡（范围卡/表单卡/列表容器卡）、浅底卡（仓库/项目/信息条）、状态点 + 状态色晕卡（提示条），色值全部走 `--dsw-alias-*` token。
- 按钮语言：一律经 `GhostBtn`/`OutlineBtn`/`PrimaryBtn` 三件套显式声明 variant（宿主 `Button` 默认 `variant='ghost'`——不声明即静默降级为无框文字按钮，与对话框 outline 取消同排时"一个有框一个没框"，2026-09-05 走查修复）；对话框主行动（新建/继续更新/保存/搜索/入库所选）= primary，与宿主 `RiskConfirmation` 的 outline 取消 + primary 确认范式对齐。
- 状态直显（DSR-008，2026-09-06 互斥化）：行内至多一个**主徽章**，判别优先级 `缺失` > `挂载失败` > `已禁用` > `可更新` > `检查失败`（修复「缺失」与「已是最新」矛盾并列）；常态（已是最新/正常挂载）不占位，正常行零徽章。次要标记（`本地有修改`/`无 SKILL.md`/名文法风险）收进 ⋯ 菜单顶部状态区。`缺失`/`已禁用` 为本地扫描即得；`挂载失败` 来自行状态走查（点击徽章展开失败明细与修复提示词复制入口）；`可更新`/`检查失败`/`本地有修改` 来自检查缓存（`overview` 的 `upstream` 字段），无网络请求；技能库标题旁标注「上游状态检查于 HH:MM」。徽章为原生 pending pill 样式（灰底灰字；可更新深色字；仅警告态用琥珀/红）。
- 行操作收进 `⋯` 菜单（DSR-008），按来源分化（DSR-017）：外部 skill（github）为 `立即更新`、`禁用`、`移动到分组 ▸`（悬停展开分组子菜单，当前组打勾）、`删除`（红色）；缺失行以 `恢复`/`删除` 为主；禁用行以 `启用` 替代更新/禁用。自有 skill 只有 `禁用`/`启用` 与 `移动到分组 ▸`——无更新（无上游）、无删除（C-03 只读红线，由用户在文件系统自管）。行内不再放置按钮或换组下拉。`立即更新` 先对单行触发 `check`，发现 `locally_modified` 或 `baseline_missing` 时必须先显示遮罩确认对话框（明确说明覆盖范围、不会自动备份本地修改，勾选确认复选框后才以 `confirmLocalChanges` 重试）；Host 返回 `local-changes-confirmation-required` 时同样转入该对话框。
- 行菜单浮层几何：主/子菜单一律 `position: fixed` 锚定触发按钮 rect——宿主设置面板是定高 `overflow:hidden` 容器，absolute 锚行卡的弹层在分组过多时超出面板底边被裁且随行卡滚动、永远不可达（2026-09-05 走查修复）。规则：下方空间不足自动向上翻，子菜单左侧空间不足向右翻；max-height 按视口可用空间封顶 + 内部滚动，主/子菜单均 `overscroll-behavior: contain`（滚到边界不链动外层，否则外层一滚 rect 失效、菜单被自己的滚动关掉）；任何外层滚动或窗口缩放即关闭菜单（rect 失效），主菜单内部滚动仅收起子菜单，子菜单内部滚动菜单保持（2026-09-10 走查修复：子菜单渲染在主菜单 ref 之外，滚动被误判为外层滚动，分组多时滚一下整菜单即消失）。
- 警告条：存在非行级警告（未匹配工作区引用等）时在技能库上方显示琥珀提示条，逐条列出并附修复提示词复制入口。
- 操作结果反馈（2026-09-06 改版）：**成功事件走宿主 Toast 原语**（顶中浮层、hold 3s 渐隐、seq key 连播重启；原语缺失时内置同几何 token 浮层兜底，反馈绝不静默丢失），入口在技能页根挂载一次、两视图共享 `showToast`；**warn/error 维持内联卡**（需读原因与复制修复提示词的不自动消失）。行操作成功另加**行高亮渐隐**（品牌色晕 1.6s，反馈落在事情发生的对象上）。批量语义下"单条失败不断批"的结果（`update` 返回 `skipped`/`error`、`↻ 刷新` 的上游不可达计数与对账问题数）**必须走 warn 态上屏并携带原因**，禁止只进弱提示造成"确认后石沉大海"（2026-09-05 走查反馈）；`↻ 刷新` 的 check 与 sync 结果合并为一条通知，避免后写覆盖前写。挂载失败展开面板与问题存续绑定：消解即塌缩，不留空壳（2026-09-06 走查修复）。

### 配置页（Plugins 页 → 本行「配置」）

- 0.1.7 起配置入口在**侧栏 Plugins 页**本行页面上（旧设置页「插件」区的配置卡片随 `settings.plugin.item` 槽一并废除）：路径项只有「本地 skills 目录」（带原生目录选择器）；pi 接管为「接管宿主」复选框组（DSH 固定勾选不可关，pi 可选；pi 目录固定默认路径 `~/.pi/agent` 探测，不可配——DSR-019）；**两字段统一草稿语义，且进同一次原子 mutate**：无修改时保存灰掉，一切修改（含复选框）点保存才生效；保存后立即生效，技能页下次拉取即按新目录工作；配置页不提供任何库操作，管理操作全部在技能页。
- 交互按官方范式（DSR-026）：**没有「放弃」按钮、没有「未保存」标记**——编辑先暂存，点保存写入，**离开页面即丢弃**。这是官方 `SettingsForm` 的既有语义（模块注释原文 discards on unmount and offers no discard control；`onDiscard` 由卸载路径调用），本插件改为完全对齐，不再保留此前那套自绘的「放弃/未保存」交互。
- 外观由官方原语承担，本插件不自绘样式：`SettingsForm` 出框架与保存栏，`SettingsValueField` 出字段（含「已覆盖」徽章与「重置」）。唯一的自有控件是目录选择按钮与 pi 复选框所在的两行。
- ⚠ 已知未实测点：`SettingsValueField` 自带 label/input/hint 三层，而「选择…」按钮挂在 `alignItems: 'center'` 的 flex 行里与其并排——**按钮的垂直落点未在浏览器中核过**（DSR-026「尚未验证」）。

## 生命周期与副作用清单

| 副作用 | 建立 | 清理 |
|---|---|---|
| RPC channel | `apply` 内 `ctx.connection.rpc.handle('/skill-manager', ...)` | 平台 `owner.effect` 持有，随 Fiber 卸载自动摘除（DSR-014） |
| storage 域 | fiber 结算后异步 `ctx.storage.domain.open(spec)`（迁移先行） | 域句柄 `close()` 进 `ctx.effect` |
| 配置校验挂点 | `apply` 内 `ctx.on('internal/config', ...)` | `ctx.on` 返回的 disposer 随 Fiber 释放 |
| 页面策略 | `apply` 内 `ctx.settings.configure({ auto: false }, ctx.fiber)` | `configure` 返回的 disposer 进 `ctx.effect` |
| 配置对账器 | `apply` 内 `ctx.on('loader/volatile-update', ...)` + 200ms 防抖 → sync（**经注入的 WRITE FIFO 入队**，与 RPC 写同队串行，DSR-021） | `ctx.on` 的 disposer + 防抖定时器随 Fiber 释放 |
| 启动预热 | `apply` 内 1s 延迟定时器 | 定时器随 Fiber 释放 |
| 调度队列 | `apply` 内创建 WRITE FIFO（注入 `createDispatch`，与对账器共享）；NET 队列由 `createDispatch` 内建 | 随 Fiber 释放 |
| 写后收敛定时器 | Client `SkillsSection` 的 `convergeTimer`（400ms 防抖，DSR-021） | 组件卸载 `clearTimeout` |
| 缓存层 | `apply` 内创建（`src/core/base/cache.js`） | 随 Fiber 释放（纯内存） |
| 网络请求 | 每次调用创建 AbortController（API 15s / 下载 90s） | 超时或完成时 abort |
| settings.section | Client `slots.register` | 注册返回 disposer |
| 本行配置页 | Client `configForms.whileServed` → `slots.inject('plugins.row.config')` → `slots.register` | whileServed 返回的 disposer 进 `ctx.effect`（命名空间不再被服务时自动撤下） |
| 配置变更订阅 | Client `ctx.remote.$on('settings/document-updated')` | 订阅返回 disposer |
| 导航图标补丁 | Client MutationObserver | `disconnect()` |
| 组件状态 | 组件局部 | React 卸载 |

11. 未配置状态下调用各方法，确认统一 `skilldir-unconfigured` 且无任何目录读写。
