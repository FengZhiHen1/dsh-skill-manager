# dsh-skill-manager 需求

## 权威范围

本文唯一拥有 `dsh-skill-manager` 的目标、用户、场景、功能范围、需求约束、外部依赖、非目标与验收条件。业务语义细则归 `technical-details/`，选型与取舍理由归 `decisions/`。本文不指定实现机制、平台接口、存储载体或部署形态；既有设计结论（含 `decisions/` 与技术文档中的已确认选择）不构成需求约束，后续设计可重新裁定。需求结论的出处见 `decisions/` 与用户确认记录，本文仅在追溯处引用旧编号。

## 结论先行

- 核心需求：一个集中 skills 目录（目录即库，只读）+ 按「分组 → 挂载」分发到 DSH 全局根与各工作区。
- 附加需求：外部 skill（插件下载入库的）的完整生命周期——搜索下载、检查更新、删除出库（备份与恢复）。
- 红线：配置目录内文件一律只读，插件可写范围仅限其自行下载的外部 skill。
- 失败处理：自动执行限于绝无歧义的安全操作；预期外失败除清晰提示外，提供一键复制的修复提示词（含完整上下文与推荐方案）交本地 Agent 处理。
- v1 不含：本地导入、同步矩阵与健康视图、工作区既有条目的接管。

## 目标

- 让 DSH 设置页成为集中 skills 目录的管理入口：查看库、分组、配置全局与工作区挂载、禁用、下载与维护外部 skill，全程在 GUI 内完成，无需手工搬目录或建链接。
- 管理入口与已配置内容在 DSH 重启后仍然存在。

## 背景与问题

用户在本机维护一个集中 skills 目录（skill 平铺、各含 `SKILL.md`）。DSH 会从用户级与项目级 skill 根发现 skill，但把目录分发到不同工作区需要手工搬目录、建链接。本插件补上这个管理面：目录即库，分组即分发单位，挂载目标即 DSH 自己的 skill 根，用户无需改动 DSH 组合配置。

## 用户与场景

- 主要用户：本机 DSH Web GUI 用户。
- 管理场景：在设置页查看库内 skill，建组、换组、配置全局与工作区挂载、禁用、删除外部 skill。
- 获取场景：搜索公开注册表或输入 GitHub 仓库，选择候选 skill 入库并按组上架。
- 维护场景：检查外部 skill 的上游更新、确认本地修改后执行更新、恢复缺失目录、删除出库与恢复备份。

## 需求约束

- C-01 安装名必须匹配 DSH skill 名文法；已存在但不匹配的名字只报告为风险，不自动改名。（旧 C-01）
- C-02 挂载目标只允许 DSH 全局 skill 根与当前工作区项目 skill 根；不写其他应用的根。（旧 C-02）
- C-03 目录只读红线：配置目录内文件一律只读；插件可写范围仅限其自行下载入库的外部 skill（安装、更新、删除、恢复）；对用户自有 skill 绝不重命名、覆盖或删除。（取代旧 C-03）
- C-04 自动执行边界：自动执行（对账、物化、修复）只限于绝无歧义的安全操作，如按期望在空闲目标建立链接、摘除可证明归本插件所有的链接；工作区根中非本插件建立的既有内容一律不修改、不覆盖；存在歧义或可能误伤的情形不自动修改，转入失败呈现与修复提示词流程（R-17）。（旧 C-03 剩余部分 + 新增原则）
- C-05 插件不得向会话注入模型可见工具、Prompt 或 skill provider。（旧 C-06）
- C-06 页面不依赖浏览器本地持久化：刷新后从权威源重读。（旧 C-07）
- C-07 配置目录内不出现插件写入的状态文件或元数据。（旧 C-08）

## 外部依赖

公开 skill 注册表（skills.sh）与 GitHub 公开仓库接口是搜索、下载与检查更新的默认外部依赖；不可用时须可读呈现，且不阻断库管理与分发。

## 非目标

- 不管理其他应用的 skill 挂载。
- 不做本地导入（把本地目录或 zip 导入库）。（旧 R-11）
- 不做同步矩阵与健康视图；挂载问题以库视图行状态呈现。（旧 R-14）
- 不做工作区 skill 根既有条目的接管与迁移；既有内容一律不触碰。（旧 R-21、旧 AC-12）
- 不与既有 CLI 工具互通、不兼容其文件格式、不迁移其历史数据。
- 不为库目录维护版本历史。
- 不提供模型可调用的 skill 管理工具。
- 不支持多用户、远端权限或审计。
- 不发布 npm，不为其他机器设计安装器。
- 不提供私有仓库认证、Token 或代理配置。

## 验收条件

1. AC-01 常驻与持久：重启 DSH 后设置页入口与既有配置（目录、分组、挂载、禁用）保持。（旧 AC-01、AC-08）
2. AC-02 安装可见：从 GitHub 安装外部 skill 后库列表出现该 skill，且其挂载位置对 DSH 可发现。（旧 AC-02）
3. AC-03 DSH 发现：新建会话的 skill 目录包含已挂载 skill；当前会话的发现时机实测记录，不即时则标注为已知限制。（旧 AC-03）
4. AC-04 分发：分组挂载到 DSH 全局与两个工作区后，对应 skill 根均出现该 skill；换组或改挂载后立即按新期望生效；删除被引用的工作区后仅报告问题，不删除项目目录。（旧 AC-06 工作区部分、旧 R-03 验收）
5. AC-05 检查更新：用旧版本记录发起检查得到「可更新」；更新后版本信息变化。（旧 AC-04）
6. AC-06 本地修改确认：修改外部 skill 文件后检查报告「本地有修改」；未确认的更新被拒绝且不写任何文件；UI 显示完整遮罩确认，确认后更新才执行。（旧 AC-05）
7. AC-07 出库与恢复：删除外部 skill 后库与挂载位置均不再出现且备份存在；恢复后目录、来源与组归属还原。（旧 AC-07）
8. AC-08 禁用：禁用后挂载位置无该 skill 而库内目录保留；启用后恢复；禁用期间检查不把该条目报告为缺失。（旧 AC-08）
9. AC-09 卸载：移除插件后管理入口消失、DSH 正常启动、已挂载 skill 仍在挂载位置。（旧 AC-10）
10. AC-10 目录配置：未配置时管理操作返回可读「未配置」错误且页面显示引导；配置空目录后库为空、分组与挂载可用；改配另一目录后立即按新目录工作、旧目录挂载保留为孤儿；配置指向不存在目录时返回可读错误且插件保持可用。（旧 AC-13）
11. AC-11 并发与损坏：两个页面同时提交不产生交错状态；状态介质损坏时操作报可读错误而非静默丢数据。（旧 R-17 验收）
12. AC-12 错误呈现：断网、仓库不存在、路径不可写时页面均显示对应可读错误，其余功能不受影响。（旧 R-19 验收）
13. AC-13 只读红线：对库内用户自有 skill 执行任何操作（含换组、改挂载、刷新、删除入口等）后，其文件内容与元数据不变；对外部 skill 的更新或删除不影响任何其他条目。（新增）
14. AC-14 基线保护：所有验收不得通过放松断言、跳过检查、篡改阈值或伪造通过证据达成；基线类指标只允许改进，不允许回退。（旧 AC-11）
15. AC-15 修复提示词：触发一次预期外失败（如目标不可写、仓库不存在、物化冲突）后，界面显示清晰错误且提供一键复制入口；复制出的修复提示词包含完整上下文（操作、错误、相关路径与配置）与推荐处理方案，可直接交给本地 Agent 处理。（新增）
